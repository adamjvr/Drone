# License and Rights Status

## Repository source license

**No project source-code license has been selected in this phase.** Do not infer a license from the reverse-engineering goal or from licenses used by unrelated projects.

Before a public release intended for outside contribution or redistribution, the project should deliberately choose a source license and add the corresponding `LICENSE` file. Until then, normal copyright defaults apply to newly authored project source/documentation.

## Original Drone material

The original game executables, artwork, audio, level data, demos, and other proprietary payloads are not relicensed by this project. They are kept outside Git under the local `.reference/` workflow.

Publishing independently written source code and technical specifications does not by itself establish rights to distribute the original commercial/shareware assets as part of a new packaged game.

## Future remaster assets

A public remaster can ultimately use one or more of these models, depending on rights and project decisions:

- user supplies an original lawful data set and the new engine imports it locally;
- the project obtains permission/license to distribute original assets;
- replacement assets are created under a separately documented license;
- fidelity and replacement-asset modes coexist.

The repository architecture is designed so this distribution decision does not have to dictate the simulation architecture.

## Contributions

Until a source license/contribution policy is selected, outside contributions should not be solicited as though their licensing terms were already settled. When public collaboration begins, update `CONTRIBUTING.md` with the selected inbound contribution terms.
