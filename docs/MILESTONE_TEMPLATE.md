# Milestone/Phase Documentation Template

Copy this structure for future phase documents.

## Objective

State the behavioral/reconstruction capability this phase is intended to establish.

## Entry evidence

List exact evidence binaries/files and the prior findings this phase depends on.

## Completed work

For each major item include:

- what was learned/built;
- evidence IDs and relevant addresses/files;
- confidence;
- clean implementation/tests added;
- known limitations.

## New/revised findings

Summarize changes to function/global/structure/format knowledge and link the durable ledger/spec entries.

## Validation

Record commands/tests/reference comparisons actually executed. Distinguish synthetic tests from original-data/reference tests.

## Open discrepancies

Record mismatches or unresolved behavior instead of silently accepting them.

## Documentation updated

At minimum consider:

- `STATUS.md`;
- `ROADMAP.md`;
- `RESEARCH_LOG.md`;
- function/global maps;
- structure/correspondence/findings/question ledgers;
- relevant subsystem/format docs;
- Ghidra scripts.

## Exit criteria

Use objective conditions, not “looks good.”

## Handoff / next phase

State the next highest-value tasks in dependency order.
